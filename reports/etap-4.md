## ЗАДАЧА 1 — пагинация (backend)

`BaseParser.search(query, region, limit_pages: int = 3)` — новый параметр, сбор с нескольких страниц.
Парсеры используют переиспользуемый HTTP-клиент (`BaseParser._client`, инжектируется в тестах),
дедупликация по ссылке и ранняя остановка, когда страница не дала новых товаров.

### Kufar

Проверено на живом сайте: HTML-страница выдачи игнорирует `page`, но в `__NEXT_DATA__`
`listing.pagination` лежат cursor-токены страниц. Реализация:

- страница 1 — HTML `kufar.by/l?query=...`, из `__NEXT_DATA__` берём `ads` и токены;
- страницы 2..N — `api.kufar.by/search-api/v2/search/rendered?query=...&size=50&cursor=<token>`;
- стоп: страница без новых товаров или токен отсутствует.

Результат по «монитор»: **143 товара** (43 + 2×50).

### Onliner

`sdapi/catalog.api/search/products` игнорирует `size`, но поддерживает `limit` и `page`.
Реализация: `limit=100&page=1..N`. Результат по «монитор»: **298 товаров** (100+100+100, часть
дублей отсеяна).

## ЗАДАЧА 2 — умные фильтры и категории

`backend/app/parsers/categories.py`:

- **Бренды**: словарь `BRANDS` (samsung, apple, xiaomi, lg, asus, lenovo, hp, dell, sony, intel,
  amd, nvidia) с вероятными категориями и вариантами типа устройства. Поиск по слову с границами
  слова (`\b...\b`).
- **Классификатор** `classify(query)` теперь возвращает **список категорий**: совпадения по
  ключевым словам + категории бренда. «samsung» → `["phones", "monitors", "tv"]`.
- **Новые фильтры**:
  - monitors: «Тип матрицы» (IPS/VA/TN/OLED), «Встроенные динамики», «Изогнутый экран»;
  - phones: «Объем памяти», «Цвет»;
  - laptops: «Накопитель»;
  - новая категория tv (телевизор/TV): «Диагональ», «Разрешение», «Тип матрицы», «Smart TV».
  - если найден бренд и нет фильтра `device_type` — в начало добавляется «Тип устройства» с
    вариантами бренда (для Samsung: Смартфон, Монитор, Телевизор, Планшет, Ноутбук).

`GET /api/filters` теперь возвращает `{"query", "category" (первая), "categories": [...], "filters": [...]}`.

Frontend:

- при вводе «samsung» появляются фильтры бренда (тип устройства + категории);
- выбранные фильтры подсвечиваются (класс `.checkbox.selected`);
- кнопка «Очистить все» сбрасывает выбор (`clearFilters` в Zustand-сторе).

## ЗАДАЧА 3 — внутренняя навигация

Выбран надёжный вариант без новых окон PyWebview — **страница внутри приложения с iframe**:

- карточка товара ведёт на SPA-роут `/product?url=<ссылка>` (React Router);
- страница показывает кнопку «← Назад к поиску» и iframe;
- внешние сайты (Kufar/Onliner) запрещают фрейминг (`X-Frame-Options: SAMEORIGIN`), поэтому
  добавлен backend-прокси `GET /proxy?url=...`: серверно загружает страницу через httpx и отдаёт
  её без заголовков `X-Frame-Options` / `Content-Security-Policy` (и без content-* служебных
  заголовков). Проверка url: только `http(s)`.
- в dev-режиме Vite проксирует `/proxy` на `127.0.0.1:8000`.
