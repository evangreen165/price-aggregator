## ЗАДАЧА 3 — парсеры Ozon и Wildberries (backend)

Заглушки заменены реальными классами `backend/app/parsers/wb.py` и `backend/app/parsers/ozon.py`,
зависимость `curl-cffi` добавлена в `pyproject.toml`. Оба используют `impersonate="chrome"`,
прогрев cookie-сессии главной страницей, дедупликацию по ссылке и `BaseParser._apply_filters`.

### Wildberries

- `https://search.wb.ru/exactmatch/ru/common/v4/search?query=...&dest=...&resultset=catalog&page=N`.
- Поля: `name`, `salePriceU` (копейки, делим на 100), `id` → ссылка
  `https://www.wildberries.ru/catalog/<id>/detail.aspx`.
- Базовая пагинация через `page` (до `limit_pages`), стоп на пустой странице.

### Ozon

- `https://www.ozon.ru/api/composer-api.bx/page/json/v2?url=/search/?text=...` через curl_cffi.
- Поиск товаров рекурсивно по `widgetStates` (JSON-виджеты): объекты с `title` + `price`
  (`price`/`cardPrice`, строка или число) + `skuId`/`id` → ссылка `https://www.ozon.ru/product/<id>`.
- Playwright намеренно не добавляем (тяжёл для `.exe`); при недоступности API парсер возвращает
  пустой список, не роняя остальные маркетплейсы.

**Ограничение проверки**: с IP этой машины WB/Ozon отдают 403/498 (антибот), поэтому live-проверка
здесь невозможна — в smoke-тестах `wb: 0 items`, `ozon: 0 items`, `errors: {}` (парсеры корректно
деградируют). На машине пользователя прогрев сессии (первый GET на wildberries.ru/ozon.ru для
cookie) может дать реальные данные. Логика парсинга покрыта моками в тестах.
