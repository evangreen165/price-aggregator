**Корень зависания (устранён)**: pywebview при инъекции JS-моста рекурсивно обходит атрибуты
`window._js_api`. Наш `DesktopApi` хранит ссылку на окно (`api.window`), и обход заходил в
`window.native` (нативный WebView2-контрол), чьё дерево доступности (`AccessibilityObject ->
Bounds -> ...`) рекурсируется без границ → `maximum recursion depth exceeded` в GUI-потоке.

**Фикс**: `api.window._serializable = False` после создания окна — pywebview пропускает такой
атрибут при обходе (`get_functions` проверяет `_serializable`), а `api.window` остаётся
доступным для `open_link()`. Плюс превентивно:
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-renderer-accessibility`.

**Проверка на собранном `.exe`** (лог 22:48): 5 шагов запуска → страница загрузилась
(GET /, /assets/* 200) → поиск работает многократно (поиски «телевизор», «монитор»,
«монитор 27» из UI в 22:49–22:50, все 200) → **рекурсии нет** (0 новых записей), процесс
жив и обслуживает запросы. Ранее (22:37) тот же сценарий ронял процесс.
