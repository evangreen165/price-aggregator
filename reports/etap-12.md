## ЗАДАЧА 2 — расширение лимитов 21vek (не выполнено, задокументировано)

Исследование: `?term=телевизор&page=N` для N=2..4 возвращает **ту же страницу 1**
(`paginationMeta: {"currentPage": 1, "totalPages": 167, "total": 10000}`), т.е. SSR игнорирует
`page` (и `offset`/`from`/`limit`/`sort`). Пагинация в 21vek происходит клиентским XHR
(`gate.21vek.by/search-composer/...`), который:
- не вызывается при загрузке и скролле страницы (перехват даёт только cart/suggest/pulse);
- GET/POST к `search-composer/api/v1/search` → 404;
- кнопок пагинации в DOM нет.

**Итог**: доступными методами 21vek отдаёт только первую страницу (60 товаров). Парсер оставляет
цикл по страницам (дедупликация не даёт дублей) — безопасно, но >200 недостижимо без закрытого
XHR. Зафиксировано как известное ограничение.

  В `Product` добавлено поле `rating` (заполняется AliExpress из `pdpInfo.preloadedData.rating`).

  пагинация и «найдено N» считаются по отфильтрованному/отсортированному списку.

## ЗАДАЧА 4 — Deal.by и AliExpress

- **Deal.by**: исследование (`research/test_deal_dom.py`) — после прокрутки 8×3000px ни одного
  `.product-card`/`.product-item`/`/item/`-элемента. Публичного API нет (404). По ТЗ **удалён из
  UI и реестра** (файл `dealby.py`, тесты и чекбокс удалены).
- **AliExpress**: добавлен перехват `aer-webapi/v2/recommend` + скролл/ожидание; стабильность
  с текущего IP не достигнута (в прогонах 0 товаров, страница флаки). Оставлен best-effort,
  в UI подписан **«AliExpress (нестабильно)»**.
