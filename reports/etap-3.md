Дата: 2026-11-12
Ветка: `main`

## ЗАДАЧА 1 — исправленные UX-баги

### 1. Внешние ссылки открываются в системном браузере

Карточка товара на странице «Поиск» теперь отдаёт ссылку с `target="_blank"` и
`rel="noopener noreferrer"`. PyWebview перехватывает `_blank`-переходы и открывает их в
системном браузере (Edge/Chrome); окно приложения и его состояние остаются на месте, «застревания»
нет. Изменение в `frontend/src/pages/SearchPage.tsx` (компонент `ProductCard`).

### 2. Состояние поиска сохраняется при переключении вкладок

Поставлен лёгкий стейт-менеджер **Zustand** (добавлен в `package.json`), создан стор
`frontend/src/store/search.ts`. В стор подняты:

- `query`, выбранные маркетплейсы;
- статус поиска (`idle/loading/success/error`), результаты по маркетплейсам, ошибки;
- доступные фильтры, категория, выбранные значения фильтров.

`SearchPage` стала тонким компонентом, читает/пишет стор. Zustand-стор живёт вне дерева React,
поэтому при уходе на «Плагины»/«Настройки» и возврате результаты, запрос и фильтры не теряются.

## ЗАДАЧА 2 — динамические фильтры

### Backend

`backend/app/parsers/categories.py`:

- `classify(query)` — классификатор по ключевым словам: `монитор/экран/дисплей/display` →
  `monitors`; `телефон/смартфон/iphone/айфон/phone` → `phones`; `ноутбук/laptop/ultrabook/макбук` →
  `laptops`; иначе `general`.
- Для каждой категории словарь фильтров:
  - monitors: Диагональ, Разрешение, Частота обновления;
  - phones: Бренд, ОС;
  - laptops: Бренд, Оперативная память.
- `filters_for_query(query)` возвращает список фильтров для распознанной категории.

`backend/app/main.py` — эндпоинт:

```
GET /api/filters?query=монитор
→ {"query": "монитор", "category": "monitors", "filters": [{"key", "label", "options"}, ...]}
```

### Frontend

На странице поиска при вводе текста (дебаунс 400 мс) делается запрос к `/api/filters`.
Под строкой поиска отрисовываются группы фильтров (чекбоксы). Выбор хранится в сторе
(`selectedFilters: Record<key, string[]>`), работает как обычное состояние UI. Передача фильтров
в парсеры — следующий шаг (в интерфейсе это подписано).

Примеры: «монитор» → чекбоксы разрешения и частоты; «iphone» → бренд и ОС.
